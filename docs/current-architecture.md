## 2. アプリケーションの責務

本アプリケーションは、ユーザーまたはグループに紐づく外部HTTPリクエスト定義を管理し、APIまたは時間トリガーから実行するLaravelアプリケーションである。あわせて、実行可否に使用する祝日情報と1回限りのスキップ情報を管理する。

実装されている主な責務は次のとおりである。

- Google認証によるグループおよび所有者ユーザーの登録
- APIトークンによるAPI認証
- 外部HTTPリクエスト定義の登録、一覧、更新、論理削除
- 単体コマンドおよびまとめコマンドの手動実行
- 時刻、曜日、祝日、個別カレンダー、スキップ情報に基づく定期実行
- 定期実行結果の保存、取得、世代管理
- Google Calendar APIから取得した各国の祝日情報のファイルキャッシュ
- ユーザーまたはグループ単位の休日上書き
- ReDocによる一部API仕様の表示

## 3. 対象外または未実装の機能

リポジトリ内に設定、テーブル、モデルの一部が存在していても、次の機能は完結した利用経路を確認できない。

- 一般ユーザー向けの画面。アプリケーション固有の画面テンプレートはなく、画面に相当するものはReDocのみである。
- SSID変化の受信、状態更新、コマンド実行。関連テーブルはあるが、SSID自体とSSID状態のモデル、API、実行処理がない。
- FCM通知。`fcm_token` と通知対象の抽出処理はあるが、送信処理はTODOのままである。
- `command_id` が `-1`、`-2`、`-3` の端末モード変更。名称変換と対象ユーザー抽出はあるが、端末へ変更を送る処理はない。
- キューによる非同期処理。キュー設定はLaravel標準のまま存在するが、ジョブ実装はなく、既定値は同期実行である。
- メール送信、ブロードキャスト。設定ファイルはあるが、アプリケーションからの利用箇所はない。ブロードキャストサービスプロバイダーは無効化されている。

| Artisanコマンド | Laravel Scheduler上の頻度 | 現在の処理 |

## 7. 主要ユースケースとデータフロー

### 7.1 Googleログイン

1. クライアントが `/auth/redirect` にアクセスする。
2. Laravel SocialiteがGoogle認証画面へリダイレクトする。
3. Googleが `/login/callback` へ戻す。
4. コールバックはステートレスでGoogleユーザー情報を取得する。
5. Googleのメールアドレスで `groups` を登録または更新し、Googleトークンを保存する。
6. グループ所有者が未登録の場合、60文字のランダムなAPIトークンを持つ `users` を作成する。
7. APIトークン、ユーザー名、所有者フラグをJSONで返す。

`GoogleLoginController::apiLogin()` にはGoogleトークンからログインする処理があるが、対応するルートはない。

### 7.2 コマンド管理

コマンドは `commands` に保存され、対象はユーザーまたはグループで表現される。HTTPメソッド、URL、本文形式、ヘッダー、パラメーターを文字列として保持する。

- 登録時は、対象種別、名前、URL、HTTPメソッド、本文形式等を検証する。
- 一覧時は、認証ユーザー自身と所属グループを対象に検索する。
- 更新および削除時は、対象ユーザーまたはグループに所属するかを確認する。
- 削除は `deleted_at` を設定する論理削除である。Eloquentの `SoftDeletes` は使わず、各クエリが明示的に削除状態を扱う。

### 7.3 手動の外部HTTP実行

1. APIトークンでユーザーを認証する。
2. 単体実行では `commands`、まとめ実行では `summarize_commands` を取得する。
3. 実行対象に対するユーザーまたはグループの権限を確認する。
4. 保存済みヘッダーとパラメーターからGuzzleのリクエストオプションを作る。
5. パラメーター内の `##DATETIME##` をPHPサーバーの現在日時で置換する。
6. リダイレクトを許可して、外部URLへ同期リクエストを送る。
7. 外部レスポンスの名前、状態コード、ヘッダー、本文をAPIレスポンスとして返す。

手動実行の結果は `exec_results` に保存されない。

### 7.4 時間トリガーによる外部HTTP実行

1. `time:trigger` が、現在時刻を各トリガーのタイムゾーンへ変換する。
2. 実行時間帯、開始時刻からの実行間隔、実行フラグに合う `time_triggers` を抽出する。
3. 未使用の `onetime_skips` があれば、そのスキップを使用済みにして実行しない。
4. Google Calendar由来の祝日と `calenders` の上書きを使って休日判定を行う。
5. 休日設定と対象曜日に合わないトリガーを除外する。
6. 保存済みのコマンド情報からGuzzleの非同期リクエストを作り、Poolで実行する。
7. 成功時とHTTPエラー応答時のレスポンスを `exec_results` に保存する。
8. `exec_notify` が有効な場合は通知対象ユーザーを抽出するが、実際の通知は送信しない。

### 7.5 祝日取得と個別カレンダー

Google Calendar APIの祝日カレンダーを、国コードと年の組み合わせで取得する。取得結果は `logs/holidays.json` に保存し、同じ国と年の次回参照時に再利用する。

休日判定APIでは、最初にGoogle Calendarの結果を参照し、同じ対象日、対象ユーザーまたはグループの `calenders` が存在する場合は、その値を優先する。

### 7.6 ワンタイムスキップ

`onetime_skips` は時間トリガーまたはSSIDトリガーを対象に複数件登録できる。時間トリガー実行時に未使用スキップが見つかると、`deleted_at` を設定して使用済みにし、その実行を飛ばす。

APIからの削除は最古の未使用レコードに対してEloquentの `delete()` を呼ぶ。モデルは `SoftDeletes` を使用していないため、APIからの削除は物理削除になる。

## 8. 日付、休日、タイムゾーン、重複実行の現在仕様

### 8.1 基準タイムゾーン

- Laravelのアプリケーションタイムゾーンは `Asia/Tokyo` である。
- ローカルのPHP設定も `Asia/Tokyo` である。
- ローカルMySQLコンテナの環境変数は `TZ=Asia/Tokyo` である。
- 時間トリガーは `+09:00` のような6文字のUTCオフセットを保持する。
- 時間トリガーのSQLは、データベースの現在時刻を `+09:00` からトリガーのオフセットへ変換する。

### 8.2 時間トリガーの判定

- 開始時刻と終了時刻の範囲は `BETWEEN` で比較され、両端を含む。
- 実行間隔は、トリガー側の現在分と開始時刻の差を分単位で計算し、`exec_interval` の剰余が0かで判定する。
- 曜日はMySQLの `DAYOFWEEK` を使用するため、日曜日が1、土曜日が7である。
- 開始時刻が終了時刻より後になる日跨ぎの時間帯を特別扱いする処理はない。

### 8.3 休日判定

`holiday_decision` の現在の意味は次のとおりである。

| 値 | 実行条件 |
| --- | --- |
| `exec` | 休日の場合に実行する。曜日条件は見ない |
| `not_exec` | 休日ではなく、対象曜日に含まれる場合に実行する |
| `not_check` | 休日を見ず、対象曜日に含まれる場合に実行する |

Google Calendarの休日結果より、ユーザーまたはグループの `calenders.is_holiday` を優先する。

### 8.4 重複実行

現在の実装には、同一トリガーの同一時刻実行を一意にするキー、データベースロック、Laravel Schedulerの重複防止指定がない。そのため、次の場合は同じ外部HTTPリクエストが複数回送られ得る。

- `time:trigger` が同じ分に複数回起動された場合
- 前回の `time:trigger` が完了する前に次回が起動された場合
- 複数サーバーが同じデータベースに対してSchedulerを起動した場合

外部HTTPリクエストには冪等性キーを付与する共通処理もない。

## 9. データベース

### 9.1 テーブル一覧

| テーブル | 役割 | 主な論理参照先 |
| --- | --- | --- |
| `groups` | Googleアカウントを起点とするグループ | `users.groups_id` |
| `users` | API利用者、グループ所属、APIトークン、通知トークン | `groups` |
| `commands` | 外部HTTPリクエスト定義 | `users` または `groups` |
| `summarize_commands` | 複数コマンドIDのJSON配列 | `commands` |
| `time_triggers` | 時間、曜日、休日条件とコマンドの関連 | `commands`、`users` または `groups` |
| `exec_results` | 時間トリガーの外部HTTP実行結果 | `commands`、`time_triggers` |
| `calenders` | ユーザーまたはグループ単位の日別休日上書き | `users` または `groups` |
| `onetime_skips` | 時間またはSSIDトリガーの1回スキップ | `time_triggers` または `ssid_triggers` |
| `ssids` | ユーザーまたはグループのSSID定義 | `users` または `groups` |
| `ssid_states` | ユーザーのSSID内外状態 | `users`、`ssids` |
| `ssid_triggers` | SSID変化とコマンドの関連 | `ssids`、`commands`、`users` または `groups` |

テーブル間の参照はID値による論理的な関連であり、SQL定義に外部キー制約はない。`target_id` と `target_type` の組み合わせで、ユーザーまたはグループを表現している。

### 9.2 スキーマ管理

- Laravelのマイグレーションファイルはなく、`docker/db/sql/*.sql` がローカルMySQLコンテナの初回起動時にテーブルを作る。
- DatabaseSeederには投入データがない。
- SQL定義には主キーと一部の一意制約以外のインデックスがない。
- 本番スキーマの適用手順およびリポジトリ内SQLとの差分は確認できない。

## 10. 現状差異と後続Issue候補

以下はIssue #208では修正せず、現在の実装差異として記録する。

### 10.1 日付と休日

- 時間トリガーの実行時刻、曜日、個別カレンダーの日付はトリガーのタイムゾーンを使用する一方、Google Calendarの休日参照日はPHPサーバーの日本時間を使用する。日付境界では異なる日を判定し得る。
- 休日判定APIの入力日は `strtotime()` と `date()` で変換される。例外捕捉では不正な日付文字列を検出できず、意図しない日付へ正規化され得る。
- Google Calendar APIの取得範囲の終了は対象年の `12-31T00:00:00Z` であり、境界の扱いはテストされていない。

### 10.2 認可と入力検証

- ワンタイムスキップの参照と削除は対象トリガーの所有権を確認するが、登録は所有権を確認しない。
- コマンド登録は `CommandRequest` で入力検証するが、更新は通常の `Request` を使用し、同等の検証をしない。
- 単体コマンド実行はコマンドの所有権を確認するが、まとめ実行はまとめコマンドの所有権だけを確認し、配列内の各コマンドの所有権と削除状態を確認しない。
- 存在しないコマンドまたはトリガーに対し、単体実行は404を返すが、更新、削除、実行結果取得等は取得結果を参照して500エラーになり得る。

### 10.3 削除状態と検索

- コマンド一覧の検索条件は、ユーザー対象とグループ対象のOR条件の後に `whereNull('deleted_at')` を連結している。生成される条件上、削除状態の絞り込みがグループ側だけに適用され、ユーザー対象では削除済みを含み得る。
- 論理削除用の列は複数テーブルにあるが、Eloquentの `SoftDeletes` は使用しておらず、処理ごとに論理削除と物理削除が分かれる。

### 10.4 外部HTTP実行

- 手動実行は同期かつAPIへ結果を返し、時間トリガーは非同期Poolかつデータベースへ結果を保存する。
- `body_type=json` の場合は、JSON文字列をデコードせずGuzzleの `json` オプションへ渡す。他の本文形式はJSONデコードした値を渡す。
- HTTP応答を持たない接続エラーでは、例外の `getResponse()` が `null` になり得るが、保存処理は必ずレスポンスオブジェクトを受け取る前提である。

### 10.5 未完了機能

- 端末モード変更用の負のコマンドIDは外部HTTPコマンドとは別に扱う意図が見えるが、端末制御処理はない。また、事前ループから後続の外部HTTPリクエスト対象を除外する処理もない。
- FCM通知対象は抽出するが、通知本文を作るだけで送信しない。
- SSID関連はスキーマと一部モデルだけが存在し、状態更新とトリガー実行経路がない。

### 10.6 API文書

- `src/redoc/openapi.yml` に記載されているAPIは実際のルートの一部だけである。
- `doc/api/` にはカレンダーと実行APIの説明があるが、コマンド管理、実行結果、ワンタイムスキップ等は記載されていない。

## 12. 後続テストの追加対象
